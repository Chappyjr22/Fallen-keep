# UI review: Fallen Keep

Baseline: published v57, source 10574e2ad6b96ec081296bce26a0d4a286933079. Reviewed 2026-09-12. Review only; no game/UI changes deployed by this audit.

## Evidence and scope

Read current markup, event bindings and responsive styles in public/start-menu.mjs, game.js, coop-ui.mjs, style.css and layout-editor.mjs; inspected the actual King comic image used by map cards. Reviewed title/setup, roster, area selection, lobby, solo/co-op HUD, level choices, transformations/chests, pause/discard, Grimoire, achievements, forge, map, travel/comics, results/save recovery and editor.

This is a source and asset review, not a browser visual certification. The custom Worker project has no compatible supervised browser-preview development server. No fresh phone/browser screenshots, touch tests, computed contrast measurements or two-device sessions were performed. Existing user screenshots provide historical context only. No automated suite rerun: no runtime code changed, and existing 184 passing tests do not certify layout.

## Design improvements and layout risks (not observed browser failures)

| Surface | Current implementation | Recommended improvement |
| --- | --- | --- |
| Title | Strong established dark green, gold and illustrated background. | Preserve composition. Make secondary navigation comfortable to tap; avoid a wholesale redesign. |
| Character selection | At widths <=760px the whole 11-hero roster precedes the selected detail/action. Mobile labels shrink to 10–11px. | Compact roster with persistent selected hero summary and reachable Continue. Keep locked heroes inspectable. Distinguish base attributes, permanent bonuses and trait effects. Verify scroll at 390px portrait and short landscape. |
| Area selection | Four cards in a three-column desktop grid; the fourth wraps alone. Most art comes from comic panels. | Keep the card style; use balanced 2x2 or four-column layout depending on width, representative section art and explicit objectives/reset behavior. |
| Solo/co-op HUD | Separate templates, repeated CSS overrides, fixed boss/control positions. Co-op uses fixed 8/16px margins rather than consistent safe-area variables. | Shared HUD regions: build left, time/objective center, health/party/actions right, minimap below. Give boss bars their own reserved area. Test overflow passives, long names, notch/safe areas and simultaneous notices. |
| Level-up cards | Generic descriptions/upgrade text; solo recipe hints, peer cards and multiple actions can produce a tall screen. | Show New/Upgrade/Mastery, current → next level, concrete stat changes where available, recipe readiness and slot use. Compact but visible teammate offers. Keep banish mode unmistakable and cancellable. |
| Pause/build | Long wrapped inventory cards; shared passive effects described in co-op prose. | Structured Weapons / Owned passives / Shared passives / Attributes. Show item owner, current level, ready recipes and charges. Keep Resume prominent and destructive actions separate. |
| Grimoire | Long text page, partly hand-written recipes, no full browsable weapon/passive catalog. | Data-driven tabs for Weapons, Passives and Transformations with icons, effects, max levels, recipes and ownership/readiness in an active run. Keep inactive-run context distinct. |
| Achievements | All records in one list; new compound milestones expose only 0/1 completion. | Filters for Available / In progress / Complete plus reward type; component checklist for mastery + time/kills + finish. This requires additional progress presentation data, not merely CSS. |
| Oathforge | Clear four-upgrade structure; numeric rank and flat +1% next purchase. | Preserve simplicity. Display current → next bonus and consistent coin art; add clearer affordable/maxed states. |
| Chests/transformations | Suspense and reveal-all exist; solo coins use a diamond glyph while co-op uses coin art. | Preserve suspense. Consistent reward iconography and transformation presentation; show consumed weapons and retained passives before choosing. |
| Comics/travel | Working chapter panels and ready states; co-op dialogue styling differs. | Shared cinematic layout and clearer “You ready / Ally ready / Saving” states. Preserve approved King art and coordinated travel. |
| Save/error screens | Useful statuses exist, but warnings compete with objective and panel content. | Persistent, wrapping error region with one clear retry path; distinguish saved, pending and connection recovery. No cosmetic “success” before acknowledgment. |
| Owner editor | Hide/show and scrolling now exist; buttons have a 38px minimum, with dense controls. | Retain current tools; group selection/transform/save actions, enlarge touch targets, keep recovery notice independent of panel. No new persistence behavior in a UI-only pass. |

## Suggested implementation batches

1. **Correctness and foundation:** fix UI-01 through UI-09; shared modal/error behavior; touch/safe-area rules. Preserve the existing menu design. Preview the courtyard replacement if new artwork is necessary.
2. **In-run clarity:** shared solo/co-op HUD, compact objectives, effective-stat/build pause view, level-up card hierarchy and result parity. Verify all reward and party pause boundaries remain authoritative.
3. **Progression/reference:** visual Grimoire, achievement filters/checklists, improved roster navigation and small forge refinements. Derive names/recipes from source definitions rather than another hand-maintained list.

Do not combine a UI pass with combat balance, save-schema changes or new equipment unless explicitly required and agreed. Compound achievement progress needs a small separate data design.

## Acceptance scenarios for implementation

- Desktop, 390x844 portrait, 844x390 landscape and 200% browser text zoom; no unreachable primary actions.
- Eleven heroes, locked selection, long trait copy, both-party-ready lobby and unavailable section explanations.
- Solo 6+6, co-op 4+4, overflow boss passives, long boss names and safe-area insets.
- Normal/mastery level offers, banish/cancel, reroll, pass, multiple transformations, 1/5-item chest reveal and teammate wait.
- Pause/resume and discard confirmation by keyboard and touch; modal focus remains usable after peer updates.
- Disconnection during first-floor objectives retains visible warning; profile failure exposes a functioning Retry.
- Permanent map legend/copy, both travel reset and throne carry behavior, save failure at run end.
- Editor sidebar collapsed/expanded, long errors and saved-draft recovery remain accessible.

## Approved first implementation pass

User approved the fixes followed by HUD, offer-card and pause improvements. Implemented in this source revision: UI-01–UI-11, plus initial dialog semantics, safe-action focus and Tab containment for UI-12. Courtyard card reuses the actual facade asset over a dark background; it is not a newly captured map screenshot. Section copy, retry handlers, connection/objective separation, co-op discard confirmation, legend/chart explanations, achievement-history text, fusion copy, effective co-op stats and results parity are updated.

Shared ui-panels.mjs owns build sections, stat presentation, passive numerical deltas, reward labels, map legend and section summaries. Solo/co-op pause now groups owned weapons/passives and shows ally-owned passive benefits separately. HUD safe-area margins, health readout, boss/action regions, responsive roster scrolling and larger touch controls are included. No combat, inventory, save schema, protocol or unlock-rule changes.

Verification: 189 automated tests pass, including new actual retry/discard handlers, item ownership and passive mastery deltas. Build passes. Browser/mobile layout, focus restoration and two-device interactions remain unverified due to unavailable compatible preview. Remaining planned work: visual Grimoire, achievement filters/component-progress data, richer weapon-specific numeric upgrade comparisons, and device-guided spacing refinement.

## Visual Grimoire and achievement pass

The follow-up pass implements the planned equipment/reference browser and achievement filtering. Equipment cards include max level, mastery text, character availability and transformation ingredients. Recipe cards identify consumed weapons, retained passives, current levels, owners and chest readiness. Oath Records includes reward filters and current-run component checks for the four starter heroes. Co-op pause links use the same screens.

Historical component-progress storage is intentionally not invented: no API or schema expansion was needed for current-run evidence plus saved completion. Richer historical partial progress remains a separate future data design. Mobile spacing and focus restoration still need hands-on verification. 193 automated checks and the release build pass.
